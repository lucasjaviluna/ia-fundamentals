## Cómo mantener la documentación

1. Consultar primero el **plan integral** antes de ampliar funcionalidades o generar nuevas lecciones.
2. Actualizar los estados del plan cuando una funcionalidad realmente quede implementada y validada.
3. Respetar la fuente única de lecciones para lectura/presentación y el alcance sin sobreingeniería.
4. Mantener diferenciadas las **demos simuladas**, las **ejecuciones locales** y los **ejemplos con modelos reales**.
5. Añadir evidencia de pruebas y, cuando exista, el enlace a la entrega o commit correspondiente.

> El temario previsto contiene 16 temas; actualmente hay dos lecciones funcionales. Las prácticas de código del futuro directorio `labs/` aún no están implementadas.
